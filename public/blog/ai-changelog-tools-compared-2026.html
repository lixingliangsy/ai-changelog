AI Changelog vs conventional-changelog vs GitHub Releases

Three common ways to produce release communication. All are real; pick by whether you need a portable file, CI automation, or a host UI.

ApproachPrimary artifactStrengthWatch-out
AI ChangelogHuman-oriented draft from commits/PRsFast first pass for Keep a Changelog style notesStill requires human review before publish
conventional-changelogGenerated sections from commit metadataFits Conventional Commits + CICommit ≠ user-facing note; noise remains
GitHub ReleasesHost release pageAssets, notifications, compare viewTied to the host; Keep a Changelog prefers a file in-repo

Rule of thumb: keep a portable changelog as source of truth, use generators as drafts, and treat hosted Releases as the announcement channel.
